### Опис проєкту

- Тема проєкту: **Smart Calculator** — науковий калькулятор на Python. Застосунок зібрано з окремих модулів, і кожен учасник команди відповідає за свій.

- Розроблені модулі:
  - `core/scientific.py` — наукові функції та константи (мій модуль)
  - `ui/app.py` — головне вікно застосунку (мій модуль)
  - `main.py` — точка входу (мій модуль)
  - `core/tokenizer.py`, `core/evaluator.py` — розбір та обчислення виразів (Дмитрук Н.)
  - `core/history.py`, `ui/history_panel.py`, `tests/` — історія, пам'ять, тести (Бардюк С.)

- Функціональність кожного модуля:
  - **`scientific.py`** — мій модуль. Містить тригонометричні функції (`sin`, `cos`, `tan` та обернені до них), логарифми (`log` за основою 10 і натуральний `ln`), квадратний корінь, експоненту, модуль числа й факторіал, а також константи `pi` та `e`. Головна ідея модуля — функція `build_functions()`, яка збирає словник «назва функції → сама функція» залежно від обраного режиму кутів. Стандартний модуль `math` завжди працює в радіанах, тому в режимі DEG аргумент переводиться в радіани на вході, а результат обернених функцій — назад у градуси на виході. Для кожної функції з обмеженою областю визначення я додав перевірку: корінь з від'ємного числа, логарифм нуля чи від'ємного числа й факторіал дробового або від'ємного числа повертають зрозуміле повідомлення, а не аварію програми.
  - **`ui/app.py`** — мій модуль. Вікно на CustomTkinter у темній темі: дисплей, блок наукових клавіш, цифрова клавіатура, перемикач DEG/RAD, окремий рядок для повідомлень про помилки та керування з клавіатури (Enter — обчислити, Escape — очистити). Вікно не виконує жодних обчислень самостійно: усе, що ввів користувач, передається у функцію `evaluate()` з модуля Назара разом зі словником моїх функцій. Кольори клавіш винесено в константи на початку файлу, тому весь інтерфейс можна перефарбувати в одному місці.
  - **`tokenizer.py` і `evaluator.py`** — розбирають вираз на токени та обчислюють його алгоритмом сортувальної станції без використання `eval()`.
  - **`history.py`, `history_panel.py`, `tests/`** — збереження історії обчислень у файл, клавіші пам'яті M+ / MR / MC і 56 тестів на pytest.

- Технологічний стек: Python 3.13, CustomTkinter 6.0, pytest 8.3, Git, GitHub, VS Code.

#### Що конкретно було зроблено мною

1. **Налаштування середовища.** Встановив Git і перевірив версію командою `git --version`. Задав `user.name` та `user.email`, а також `init.defaultBranch main` і `pull.rebase false`. Створив акаунт на GitHub, увімкнув двофакторну автентифікацію, згенерував SSH-ключ командою `ssh-keygen -t ed25519`, додав публічний ключ у налаштування акаунта й переконався, що з'єднання працює: `ssh -T git@github.com` привітало мене за іменем користувача.
2. **Тренувальний репозиторій.** Перед роботою над спільним проєктом створив локальний репозиторій `git-practice`, виконав `git init`, додав файл, подивився стан через `git status`, зробив два коміти й переглянув історію командою `git log --oneline`. Це дало зрозуміти різницю між робочою директорією, індексом і репозиторієм.
3. **Клонування.** Прийняв запрошення стати collaborator і склонував спільний репозиторій по SSH: `git clone git@github.com:USERNAME/smart-calculator.git`.
4. **Власна гілка.** Створив гілку `feature/gui-scientific` командою `git switch -c feature/gui-scientific`, написав модуль наукових функцій і графічний інтерфейс, зробив кілька комітів за конвенцією Conventional Commits (`feat(scientific): add trigonometry with deg/rad support`, `feat(ui): add main calculator window`) і відправив гілку на сервер.
5. **Pull Request.** Подав Pull Request із текстом `Closes #2`, призначив рецензентом Дмитрука Н. За його зауваженням доопрацював обробку помилок: помилка більше не стирає введений вираз, а показується окремим рядком під дисплеєм. Після схвалення PR було злито, після чого я оновив локальну `main` (`git switch main`, `git pull`) і видалив уже непотрібну гілку.
6. **Code review.** Переглянув Pull Request Бардюка С. з історією обчислень і пам'яттю та схвалив його.
7. **Робота у VS Code.** Частину комітів і перемикання гілок виконував через панель Source Control у VS Code, а не лише в терміналі.

### Висновки

До цієї лабораторної я уявляв Git як спосіб зберігати резервні копії власного коду. Робота втрьох показала інше: головна цінність Git — не історія, а **можливість працювати одночасно й не заважати одне одному**. Поки я писав інтерфейс у своїй гілці, Станіслав писав тести, і жоден з нас не зламав роботу іншого, бо гілка `main` увесь час залишалася робочою.

Найкорисніший для мене досвід — code review. Мій Pull Request не злили одразу: Назар звернув увагу, що при помилці обчислення я затирав уведений вираз, і користувачеві довелося б набирати його заново. Сам я цього не помітив, бо тестував лише правильні вирази. Це і є та причина, чому код переглядає інша людина.

Технічно найцікавішим було переведення градусів у радіани. Спершу я просто викликав `math.sin()` і не міг зрозуміти, чому `sin(30)` дає `-0.988` замість `0.5`. Виявилося, що `math` завжди очікує радіани, і потрібне перетворення на вході, а для обернених функцій — ще й на виході.
